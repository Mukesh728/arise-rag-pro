💡 Viva Knowledge: Ingestion & Chunking

Why ~500 Tokens with 50 Token Overlap?

Large language models have context windows, and embedding models lose semantic granularity if chunks are too large (e.g. 2000 words). A 500-token window preserves a complete conceptual paragraph or definition. The 50-token sliding overlap ensures that a concept split across chunk boundaries isn't truncated mid-sentence.

How Are Citations Grounded by Page?

During PDF extraction, pypdf records the exact 1-indexed page index of each character range. Each chunk embeds page_number in its Chroma metadata. When retrieved, citations map directly back to the textbook page for student verification.

Dual Indexing (ChromaDB + BM25):

When a PDF is uploaded, chunks are simultaneously stored in ChromaDB (for dense semantic retrieval) and registered in the in-memory BM25 Okapi index (for keyword retrieval).

📐 Why Hybrid RRF Outperforms Pure Vector Search

Dense Vector Search (ChromaDB): Encodes semantic meaning via embedding cosine similarity. Excels at paraphrase matching but can miss exact terminology (e.g., acronyms like "FCFS", "HRRN", "SCAN").

Sparse BM25 Keyword Search: Exact term frequency + IDF scoring. Excels at technical keywords, definitions, and syllabus code names but misses semantic variations.

Reciprocal Rank Fusion (RRF): Formula: RRF_Score(d) = Σ [ 1 / (60 + rank(d)) ]. Because vector similarity scores and BM25 scores have completely different scales, RRF merges candidate lists based strictly on their relative ranks, eliminating score calibration errors.
